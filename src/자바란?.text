** 자바란? **
자바는 표준 스펙과 구현...이 따로 존재하는데,
하나의 표준 스펙을 바탕으로 여러 회사에사 각기 다른 자바를 만든다(?)

** 컴파일과 실행 **
자바 -> 컴파일 -> class 파일 생성 -> JVM에서 실행
컴파일 과정에서 .java -> .class 로 바꿔주는 과정을 원래는 javac 라는 프로그램으로 컴파일해야함.
현재는 intellij에서 자동으로 적용해주는 중

out 폴더를 열어보면 컴파일된 클래스들을 확인 할 수 있는데 주석 부분이 지워진 것을 볼 수 있음.

**자바는 운영체제의 독립성 덕분에 각 환경에 맞추어 자바 설치가 가능하다**

Java

컴파일 결과: .class(바이트코드)
실행 주체: 각 OS용 JVM이 실행 → 같은 .jar가 Windows/Mac/Linux에서 그대로 동작(WORA: write once, run anywhere).
단서: JNI/네이티브 라이브러리(예: .dll, .so)를 쓰면 독립성이 깨질 수 있음.

C

컴파일 결과: 기계어(네이티브 바이너리)
특징: OS/아키텍처(ABI) 별로 다시 컴파일해야 함. 같은 소스라도 Windows용 .exe, Linux용 ELF는 서로 호환 안 됨.
포터블 소스는 가능(표준 C, POSIX만 쓰면)하지만 바이너리는 비이식적.

Python

실행 방식: **인터프리터(CPython 등)**가 소스를 실행(내부적으로 .pyc 바이트코드 생성)
특징: 순수 파이썬 코드는 대체로 OS 간 잘 돌아감(각 OS용 Python만 있으면 됨).
단서: C 확장 모듈(넘파이 등 네이티
